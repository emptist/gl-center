# 01-01 PLAN — one file, one link, one knowledge centre

Owner rulings 2026-11-13, verbatim: "不要链接目录结构，仅去硬link
gleam-thinking-core 那个文件，因为各自的项目中有几个版本，造成混乱必须设计
这个单一数据源"; "skill等等文档也一样处理，放在哪里，谁用谁链接就行了，
单一文件链接，说link的时候，在unix世界就是指单独文件的"; "这样在我的
gits/里面就有了一个gleam语言的skill等等资料中心。各project不用去各自为政，
混乱不堪".

## Deliverable

1. `gleam.toml` + `src/gleam_language.gleam` + `test/gleam_language_test.gleam`
   — a real Gleam package whose `////` module documentation is the
   virtual-design / entity-development note, and whose public surface is
   importable by other Gleam projects.
2. `gleam-thinking-core.md` at the repo root — the single source, hard-linked
   to the skill's authoritative copy, the glibe mirror and the speak_engl
   mirror. All four names share ONE inode.
3. `knowledge/` — **one flat level, 18 files, 0 subdirectories, 0 symlinks**.
   Each file is one `ln` to one document of the `gleam-language` skill
   (`SKILL.md`, thirteen `references/*.md`, four `workflows/*.md`). No
   mirrored directory tree. Whoever needs a file links to it.
4. `README.md` — the reference protocol: how another project imports this
   package or links a single file, how the inode is verified, and which
   writes replace a directory entry (a hard link itself cannot break).
5. `variants/` — the historical A / B / enriched snapshots as independent
   files, deliberately NOT links.

## Acceptance commands

```
gleam check
gleam test
gleam format --check src test
gleam docs build
gleam export package-interface --out /tmp/gl_pi.json
gleam build --warnings-as-errors
stat -f '%i %l' <the four thinking-core names>   # one inode, link count >= 4
cmp <canonical> <each name>                      # trivially true; stat above is the real check
find knowledge -mindepth 1 -type d | wc -l       # 0
find knowledge -type l | wc -l                   # 0  (no symlinks)
```

## Boundary

No symlinks. No directory-level link. No guard script, no sync daemon. No
business implementation. `COMPARISON.md`, `variants/PROVENANCE.md` and
`variants/diffs/` are historical evidence and stay untouched. The stale
copy-and-`cmp` wording in `knowledge/SKILL.md` is a description, not a
hazard (`cp` keeps the inode); rewriting the skill's loading protocol is
left for the owner.
